# 初期交渉生産性シートの構造とメンテナンス手順

対象: スプレッドシート「初期交渉生産性シート」(`1cy7WA-vAW_51PEpjmPNlo79ZvHB0GSPS0c2D_y9BYDg`)の「【本交渉発生日ベース】同営業日」タブほか同系統のタブ。[CLAUDE.md](../CLAUDE.md)の「KPI分析時の注意点」で触れている代表セルコピペミスの実例(2026-08-17)は本シートで発見されたもの。2026-08-18に「APソース別ブロックへのKPI行追加」作業(後述)を行った際に判明した構造・設計判断をまとめ、同種の依頼に細かい指示なしで対応できるようにしておく。

## 1. シート全体の構造パターン

この系統のタブは共通して「**合計ブロック**」+「**カテゴリ別内訳ブロック**」という2階層構造になっている。

- **合計ブロック**(「【本交渉発生日ベース】同営業日」タブでは4〜45行目): 全APソース(候補者集客チャネル)を横断した全社KPI。42種類のKPI行から成る。
- **内訳ブロック**(46行目以降): B列に入力されているAPソース名(パートナー紹介・SMAP・転機・人事部紹介・顧問名鑑登録者・その他)ごとに、合計ブロックと同じKPIをブレークダウンした行が並ぶ。**ただし内訳ブロックは合計ブロックより行数が少なく、KPIが欠落していることが多い**(2026-08-18時点で10種類欠落していた。4章参照)。

各ブロック内のKPIは以下のセクション順に並ぶ(合計ブロックの行番号は当時のもの。内訳ブロックも同じ順序):

1. 人数(合計ブロックのみ。全社共通指標のためAPソース別には存在しない・追加もしない。5章参照)
2. 初期交渉設定数 → 1AGTあたり
3. 総交渉実施数 → 1AGTあたり → 新規 → 再交渉
4. 総本交渉設定数(件) → 1AGTあたり → 新規 → 再交渉 → 片手 → 両手 → 当Q実施初期交渉から
5. 総本交渉設定数(人) → 1AGTあたり → 新規 → 再交渉 → 片手 → 当Q実施初期交渉から (※人ベースには「両手」が存在しない)
6. 割合(総本交渉設定数(人)の当Q実施初期交渉から ÷ 総交渉実施数の新規)
7. 設定数(社) → 1AGTあたり
8. 設定率(件/AP) → 新規設定率 → 設定率(人/AP) → 新規設定率
9. 一人当たり設定(件) → 一人当たり新規設定(件) → 一人当たり再設定(件)
10. 成約数(人) → 1AGTあたり → 新規 → 再交渉 → 片手 → 両手
11. 成約率(成約/設定件) → 新規成約率 → 再交渉成約率 → 片手(-) → 両手(-)
12. 平均基準年収

「転機」ブロックのみ、新規・再交渉の内訳としてさらに「当Q/前Q/2Q前からの設定(件)」「不明orマッチングから」という独自の詳細行を追加で持つ。これは転機固有の分析軸であり、他ブロックには存在しない。今後この構造をいじる際は、転機ブロックだけ行数・オフセットが他と異なる点に注意。

## 2. 代表セル+MAP/LAMBDA方式(重要・既知の落とし穴)

D列の数式は、ヘッダー行($D$1:$1に開始日、$D$2:$2に終了日が入る)に対して`map(...,lambda(start,end,...))`または`ArrayFormula`でスピル展開する「代表セル」方式。新しい行を作る際は既存行をコピーして条件の一部だけ書き換える運用のため、**書き換え漏れがあると内訳の合計が合計ブロックと一致しなくなる**(詳細事例はCLAUDE.md参照)。KPIの整合性がおかしいと感じたら、まず関連行の代表セル数式を`value_render_option='FORMULA'`で比較する。

## 4. 欠落KPI行を追加する作業手順(ワークフロー)

同様の依頼(「合計ブロックと内訳ブロックでKPI名称が一致していない/欠けている」)が来た場合の標準手順。

1. **全体をFORMULAレンダリングで取得する**: `auto/python_ss/python_ss.py`の`get_ss`系関数(またはSheets APIを直接叩く形)を`value_render_option='FORMULA'`で呼び、対象タブのA:D列を一括取得する。B/C列(ラベル)とD列(数式)を行番号付きで比較できる形に整形する。
2. **合計ブロックのセクション順序をカノニカルな並びとし、各内訳ブロックと突き合わせる**: 単純な集合比較ではなく、同じラベル(「新規」「片手」等)が複数セクションに繰り返し出現するため、**セクション単位(前後の文脈)で** 欠落を判定する。
3. **既存の内訳ブロックの兄弟行から、APソース絞り込みパターンを確認する**: どのシート・どの列で絞り込んでいるか(3章の表を参照。ただし将来的に列が変わる可能性があるため必ず現物を確認する)。
4. **新規数式は「合計ブロックの代表セル」+「絞り込み条件1つ追加」で組み立てる**。比率系(設定率・成約率・割合・1AGTあたり・一人当たり)は、合計ブロックの参照先の行オフセット構造を、内訳ブロック内の同名行の行番号に置き換えて再現する。
5. **必ず実際の「行挿入」(`spreadsheets.batchUpdate`の`insertDimension`)で物理的に行を追加する**。値だけを既存行の隙間に書き込む方式(例えば`insert_ss`のような追記関数)は使わない。行挿入なら、既存の数式内の行参照はGoogle Sheets側が自動的に追従してくれるため、挿入対象外のセルには一切触れずに済む。
6. **複数ブロックにまたがって挿入する場合は、シートの下方(行番号が大きいブロック)から先に処理する**。ある内訳ブロックへの挿入は、その内訳ブロックより下にある行だけを押し下げ、上にある行には影響しない。そのため「下から上」の順で処理すれば、既に処理し終えたブロックの行番号が後続処理で再度ズレることがない。逆に、処理順序をブロックの記載順(上から下)のままにすると、後から処理したブロック(シート上でより上に位置するもの)の行挿入が、既に処理済みの下位ブロックの行番号をさらに押し下げてしまう。**最終検証は「事前に計算した行番号」ではなく、実際にシートを再取得して「ラベルの内容」で確認すること**(2026-08-18の作業でも、処理順序の関係で転機ブロックの行番号が想定と10行ズレた実例がある)。
7. **行挿入直後は、新しい行の書式(セル表示形式)が挿入位置の直前の行から引き継がれる(`inheritFromBefore`)ため、KPIの性質(件数かパーセントか)と合っているか必ず確認・修正する**。実例: 「割合」行を件数系の行の直後に挿入したところ、パーセント表示にならず整数の「0」と表示された。挿入後は`repeatCell`で`numberFormat`を明示的に揃える。
8. **数式の意味に業務的な曖昧さがある場合(例: 分母をどのデータで取るか)は、必ずユーザーに確認してから実装する**。ロジックが確定したら本ドキュメントの5章に決定事項として追記する。
9. **全ブロック挿入後、機械的な検算を行う**: (a) D列に`#REF!`等のエラーが無いか全件チェック、(b) 追加したKPIラベルの出現回数が「合計ブロック分+ブロック数×該当項目数」の期待値と一致するか(例: 2026-08-18作業では「片手」28件・「両手」21件・「割合」7件・「新規設定率」14件が全て期待値と一致)、(c) 各ブロックの行数が想定通りか。

## 5. 既存の設計判断ログ

同じ論点を将来再度検討し直さずに済むよう、確定した設計判断を記録する。

- **2026-08-18: 「設定率(件/AP)」「設定率(人/AP)」「新規設定率」の分母は「初期交渉設定数」に統一**。旧・合計ブロックの数式は分母が「総交渉実施数」になっていたが、これはユーザー判断により誤りとされ、内訳ブロックの既存セル(元々分母が初期交渉設定数だった)に合わせる形で合計ブロック側を修正した。新規追加した「新規設定率」も同じ分母(初期交渉設定数)を使う。
- **2026-08-18: 「人数」行はAPソース別ブロックには追加しない**。全社共通のAGT人数(masta参照、日付レンジではなくメンバー名でMAPする特殊な数式)であり、APソースで分解できる性質の指標ではない。既存の「1AGTあたり」系の数式は内訳ブロックからも直接合計ブロックの人数行($D$4:$AN$4)を参照しているため、複製しても意味を持たない。
